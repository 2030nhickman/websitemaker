# SiteForge design notes

## The HTML is the source of truth

A page is an HTML fragment (the `<body>` contents). Every palette component
becomes an ordinary element tagged with `data-sf-id="sf-N"`. SiteForge never
keeps a separate copy of a component's properties. When you select an
element, `htmldoc.py` parses the HTML into a tree in which every node records
its exact character span. `components.py` then reads the properties back out
of that node's attributes and content.

Editing a property re-renders only that element and splices it into its span.
Inserting, deleting or moving an element is likewise a span edit. The rest of
your hand-written markup and formatting stays as it is, and the Code tab,
properties panel, outline and preview are always consistent.

`data-sf-id` attributes are removed on export. The `elements` tree stored in
`.siteforge` files is derived from the HTML. If a file has no `html` field,
the page is rebuilt from that tree.

### Sizes and resizing

The preview's in-page bridge (`ui/preview.py`, `BRIDGE_JS`) draws a handle on
the selected IMG, CANVAS, IFRAME, INPUT, TEXTAREA or BUTTON element. While you
drag, it resizes the element live. Images keep their aspect ratio unless
<kbd>Shift</kbd> is held. On mouse-up it posts `{type: "resize", id, width, height}`,
and Python writes the size back:

| Component | Written as |
|-----------|-----------|
| Image, Canvas, Iframe | `width="…" height="…"` attributes |
| Text Box, Button | `style="width: …px; height: …px"`. Other declarations already in `style` are kept, and 0 means auto. |

### Images

Picked or dropped image files are copied into the project's `assets` map
(`name → {mime, base64 data}`) and referenced as `assets/<name>`. The
preview and single-file export inline them as `data:` URLs. A split export
writes them to `assets/` next to `index.html`.

## Stripe

The Stripe component renders a `div[data-sf-stripe]` containing a button and
a hidden form. Keys, the price ID and the redirect URLs are stored in the
project file's `stripe` section, which is XOR-obfuscated with a SHA-256
keystream and never written into the HTML. At preview and export time the
generator adds `https://js.stripe.com/v3/` and a small runtime that defines:

- `window.siteforgeStripeCheckout(priceId?)`, which calls
  `stripe.redirectToCheckout({lineItems: [{price, quantity: 1}], mode, successUrl, cancelUrl, customerEmail?})`
  and falls back to the Payment Link URL when no key is set;
- `window.siteforgeCheckoutStatus()`, which returns `"success"`, `"cancel"` or
  `null`, based on `?checkout=` or an exact match with the configured URLs;
- click wiring for every `[data-sf-stripe] .sf-stripe-button`, and filling of
  the hidden form's `price`/`email` inputs.

The config JSON is escaped (`</` → `<\/`) so it can't close the `<script>`.

## Block → JavaScript compilation

Blocks are stored as JSON trees (`blocks.py`):

```json
{"type": "looks_show", "inputs": {"el": "button1"}, "next": {…} | null,
 "substacks": {"body": {…}}, "x": 40, "y": 60}
```

An input is a literal (string or number) or a reporter block (an object with a
`type`). `sanitize()` drops unknown block types and malformed values whenever
data is loaded.

### Output shape

```js
// Generated by SiteForge from visual blocks — edits here are overwritten.
(function () {
  'use strict';
  const sf = { vars: {"score": 0}, /* runtime helpers */ };
  window.siteforgeVars = sf.vars;

  // Script 1: when [button1] clicked
  sf.on("button1", 'click', async (event) => {
    …body…
  });
})();
```

The output is a single IIFE with no global names except `siteforgeVars`.
When no script has a hat block, the compiler outputs nothing.

### Rules

1. **Only stacks that start with a hat run**, as in Scratch. Loose stacks and
   reporters left on the workspace are ignored.
2. **Every script body is an `async` function** run through `sf.run`, which
   catches errors and logs them as `[SiteForge blocks] …`, so one failing
   script doesn't stop the others.
3. **Scripts yield like Scratch.** `repeat` and `forever` loops
   `await sf.frame()` (one `requestAnimationFrame`) at the end of every
   iteration, and `wait until` polls once per frame. Animations therefore run
   at display rate and never lock up the page.
4. **Every value is escaped.** Element IDs, variable names, text and colours
   are emitted with `JSON.stringify`-style quoting (`json.dumps`), and
   dropdown operators are checked against a whitelist. Block content can't
   inject code.
5. **Numbers**: number inputs that look numeric become JS number literals.
   Anything else becomes `sf.num("…")`, which turns non-numbers into 0.
   Text inputs that look numeric are also emitted as numbers, as in Scratch,
   where `"10"` and `10` behave the same.
6. **Elements** are looked up by their HTML `id` when the block runs
   (`sf.el(id)`). A missing element logs a warning and the block does nothing.
7. **Variables** live in `sf.vars`, keyed by name, and start from the values
   set in the Variables panel. Numeric strings become numbers.

### Hats

| Block | JavaScript |
|-------|-----------|
| when page loads | `sf.ready(() => sf.run(async () => { … }))` |
| when [el] clicked | `sf.on("el", 'click', async (event) => { … })` |
| when [key] key pressed | `document.addEventListener('keydown', e => { if (e.key === "k") sf.run(…) })` (`space` → `" "`) |
| every [n] seconds | `sf.ready(() => setInterval(() => sf.run(…), max(0.01, n) * 1000))` |
| when payment succeeds / is canceled | `sf.ready(() => { if (sf.checkoutStatus() === 'success' \| 'cancel') sf.run(…) })` |

### Statements

| Block | JavaScript |
|-------|-----------|
| set position of [el] to x y | `sf.setPosition(el, x, y)`: makes a static element `position: relative`, then sets `left`/`top` in px |
| move [el] by x y | `sf.moveBy(el, dx, dy)` |
| set size of [el] to w h | `sf.setSize(el, w, h)`: CSS width/height in px |
| resize canvas [el] to w h | `sf.resizeCanvas(el, w, h)`: canvas `width`/`height` attributes |
| set text color / background of [el] to [c] | `sf.style(el, 'color' \| 'background', c)` |
| show / hide / toggle [el] | `sf.show(el, true \| false \| null)` |
| set text of [el] to [t] | `sf.setText(el, t)` (`textContent`, never HTML) |
| clear canvas / draw circle / draw rect | `sf.clear` / `sf.circle` / `sf.rect` on the 2D context |
| if ⟨c⟩ then … else … | `if (c) { … } else { … }` |
| repeat [n] | `for (let iN = 0, nN = sf.num(n); iN < nN; iN++) { …; await sf.frame(); }` |
| forever | `for (;;) { …; await sf.frame(); }` |
| wait [s] seconds | `await sf.wait(s)` |
| wait until ⟨c⟩ | `while (!(c)) await sf.frame();` |
| stop this script | `return;` (a cap block: nothing can attach below it) |
| set [v] to [x] / change [v] by [x] | `sf.vars["v"] = x` / `sf.vars["v"] = sf.num(sf.vars["v"]) + sf.num(x)` |
| log [x] | `console.log(x)` |
| open Stripe checkout | `await sf.stripeCheckout()` → `window.siteforgeStripeCheckout()` with the configured Price ID |

### Reporters

| Block | JavaScript |
|-------|-----------|
| (variable) | `sf.vars["v"]` |
| a (+ − × ÷ mod) b | `sf.math(a, op, b)`. Dividing by 0 gives 0, and mod is always non-negative, as in Scratch. |
| pick random a to b | `sf.random(a, b)`: an integer if both ends are integers, otherwise a float |
| join a b | `(String(a) + String(b))` |
| text of / value of [el] | `sf.text(el)` / `sf.value(el)` |
| a (= ≠ < > ≤ ≥) b | `sf.compare(a, op, b)`: numeric if both sides are numbers, otherwise a case-insensitive string comparison |
| a and b / a or b / not a | `(Boolean(a) && Boolean(b))` / `(… \|\| …)` / `!(a)`. An empty boolean slot is `false`. |

### Editor behaviour (`ui/blockeditor.py`)

- Blocks are laid out again on every draw. The geometry recorded while
  drawing drives hit testing and snapping, so the model is always just the
  JSON.
- Dragging a stack block takes it and every block below it. Drop targets are:
  under any non-cap block, inside a C-block mouth, or on top of a stack
  (prepend). The snap distance is 30 px. A stack ending in a cap block can't
  be inserted mid-stack.
- Reporters snap into round slots. Boolean (hexagonal) slots only accept
  boolean reporters, and a replaced reporter is moved back onto the workspace.
- Dropping on the palette deletes. The right-click menu has Duplicate, Delete
  Block (the blocks below move up) and Clean Up. Keyboard: <kbd>Delete</kbd>,
  and <kbd>Ctrl</kbd>+<kbd>D</kbd> to duplicate.
- Click a field to edit it in a popover: an entry, a colour swatch picker,
  or a list of element IDs, variables or options.
